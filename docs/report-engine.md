Status: part 1 (libraries, pure model, writers, golden tests), the six demo forms of the enterprise edition (section "The six PVFCCo forms") and part 2 (database, API, screens: section "Part 2", migration block RPT-1 2140-2159, spec `Design/MACHVON_Design/01_Documents/05_modules/RPT.md`). Basis: eng review R9 (vetted libraries), R17 (revision lineage, stale deliveries refused), customer requirement BC.01 (official forms with exact row/column layouts; Excel kept in the template; Word narrative; file naming; issued copies per period).

## Libraries (R9)

Known cost: stale (last release Dec 2024), about 170 packages; its `uuid@8` has a moderate advisory (GHSA-w5hq-g745-h8pq) below the `high` gate. Revisit through the audit exceptions list if an advisory reaches high.

- Templates holding charts, pivots, embedded objects or macros are refused.

## Layout model (`packages/kernel/src/report-layout.ts`)
- A layout is a grid: preface rows, header rows (derived from column header paths) and body rows of kind DATA, TOTAL or NOTE.
- Cell bindings: TEXT, META, INDICATOR (a KPI code and a period basis), ROW_FIELD, ROW_NUMBER, SUM, COUNT, FORMULA.
- DATA rows reserve `capacity` lines and `EXPAND` or `REFUSE` on overflow; unused reserved lines are cleared.
- Statuses: `PENDING_EXTERNAL`, `DEMO`, `DRAFT`, `READY` (see "The six PVFCCo forms"). Formulas may use `{first:dataset}`, `{last:dataset}`, `{row}` and a row offset (`{row-1}`, `{row+1}`).
- Period kinds: MONTH, QUARTER, HALF_YEAR, YEAR, AS_OF. Bases: IN_PERIOD, YEAR_TO_DATE, AS_OF_END, FULL_YEAR, SAME_PERIOD_LAST_YEAR, PREVIOUS_PERIOD (default from the KPI's own period).
- Money is exact decimal text scaled from whole dong to đồng, nghìn, triệu or tỷ (ĐVT chip).
- No value means an empty cell plus a reported issue, never 0; a missing KPI definition is never shown; figure flags travel as issues so the issued copy carries its caveats.

## Excel fill (`apps/api/src/modules/reports/xlsx-template.ts`)
Validate the template, insert rows when the data block grew (moving everything below, including print area, conditional formats and validations), set cells, apply merges, set widths where the template has none, write deterministic bytes (the zip is normalised, same inputs give the same sha256). The template's explicit number format wins unless the layout asks otherwise. Formulas that point at another sheet, defined names and shared formulas are not rewritten on row insertion (known limit).

Stamp: when the grid carries a stamp (`grid.stamp`, set for a DEMO layout) the writer puts it in the print header (centre, red, bold) and the print footer (left) of the sheet and in the subject and description of the workbook, keeping whatever the template already prints and never repeating it. `readXlsxMarks` reads those back.

## Word (`docx-render.ts`)
Narrative blocks with `{{indicator:CODE@BASIS}}` tokens resolved by the kernel, so text and table cannot disagree. Defaults: A4, Times New Roman 13, Vietnamese administrative margins. `stamp` (the demo mark) is printed in red in the header of every page and at the start of the footer and written into the document properties; `readDocxHeaderFooter` reads those back.

## File naming (`file-name.ts`)
Default `<code>_<period>_<version>_<sha8>.<ext>`; the rule is data (pattern, version prefix and digits, max length, optional no-hash); `sha8` comes from the file bytes.

## Issued copies (`packages/kernel/src/report-issue.ts`, R17)
- Immutable; sha256 recorded; preparer, checker and approver are three different people; check/approve/issue state machine.
- A series is (organisation, layout, period); lineage by revision with `supersedes`; a correction needs a reason; the idempotency key is (organisation, layout, period, revision); copies carry the DIS snapshot id and revision.
- Marks (R18): a copy carries `marks` (`formStatus`, `demoMark`) from `issueMarksOf(layout, { demoMode })`; a copy made on a DEMO form never counts as accepted (`countsAsAcceptedCopy`; `assertAcceptable` refuses with `TEMPLATE_UNCONFIRMED`, detail `demo_not_acceptable`) and is not an acceptance that holds back a later delivery.
- A stale or superseded delivery is refused with `REPORT_OUT_OF_DATE` and the current revision; a repeat push of the same bytes is `ALREADY_DELIVERED`.

## Part 2: database, API, screens (RPT-1)

**Tables** (migrations V2140 to V2142, each with RLS forced and tenant-leading indexes): `report_template_file` and `report_output_file` (bytes by sha256, append-only, the hash is a CHECK computed by the database with `sha256(bytea)`), `report_layout` (a form registered for a tenant, one row per code and version, append-only; a DEMO layout has no `form_ref` and illustrative data, so it is never promoted: the official form is a NEW version), `report_draft` (the working copy: DRAFT, CHECKED, APPROVED, ISSUED forward only, three different people by CHECK and trigger, ISSUED frozen), `report_issue` (insert-only: triggers refuse UPDATE and DELETE and the application role has no right to them; a trigger checks that revision n+1 replaces revision n of the same series and that the copy comes from the approved draft with its files and its three people; "replaced" is derived, the newest revision of a series is its head) and `report_delivery` (append-only log of DELIVERED, ACCEPTED, REJECTED; unique per copy, receiver and event; a trigger refuses ACCEPTED for a copy made on a DEMO form). Audit and outbox are written by every command (`rpt.report_*` actions, `rpt.report.*.v1` events with ids, codes and hashes only).

**The digest of a copy**: `packageDigestOf` (kernel `report-form.ts`) is the sha256 of the lines `FORMAT:sha256` of its files in the order XLSX, DOCX. It is the `sha256` of the issued copy and what `nextIssueOf` compares, so the same files are a repeat and any changed word in either file is a new revision. The document dates of the files are the last day of the period (not the clock), so the same layout, template and data give the same bytes.

**Forms by edition**: a form is a `ReportFormBundle` (kernel): layout, narrative, receiver, period kind, data source (`LIVE` through a provider, or `ILLUSTRATIVE`) and the template bytes. The public edition registers its generic forms in `apps/api/src/modules/reports/form-registry.ts` (`DIS-WEEKLY`, READY, an AS_OF period, figures of the command center through the same reader as the screen of the leader, bound to eight codes of the KPI register; a tenant with no frozen snapshot gets empty cells and the issues `NO_FIGURE`, never zeros). The enterprise forms are added only by the enterprise seam (`apps/api/src/editions/load-enterprise.ts` calls `enterpriseReportBundles()` of `packages/edition-enterprise/src/server.ts`), so a public process never holds one (`npm run edition:check`). Figures: a provider (`ReportFigureProvider`) returns the fill data and the DIS snapshot with its revision; the funding model of FND-1 registers its own provider so that the enterprise forms, which already bind to the `ENT_*` codes, move from illustrative to live figures without a change of layout. Until then every figure on a demo form is invented and labelled so.

**API** (prefix `/report-engine`, so as not to meet `/reports/{id}` of DIS; every operation needs its permission over the WHOLE tenant, `SCOPE_DENIED` otherwise): `listReportCatalogue`; `generateReport` (fills the template, stores the files, makes the draft; a repeat of an open draft is `EXISTING`, of the head copy `DUPLICATE`, other bytes over an issued head need a `reason`); `checkReport`, `approveReport`, `issueReport` (If-Match on the draft version; the checker is not the preparer, the approver is neither, the issuer is the approver: `SELF_APPROVAL_DENIED`; wrong order `REPORT_STATE_INVALID`; a draft made before the series moved on `REPORT_OUT_OF_DATE` with `current_revision`; a demo form is judged again at issue); `listReportDrafts`, `getReportDraft` (with the preview of every cell and the cells the data could not fill), `getReportDraftFile`; `listReportIssues`, `getReportIssue` (chain, people, deliveries), `getReportIssueFile` (the bytes are checked against the recorded hash before they are given: `HASH_MISMATCH`); `deliverReport` (the kernel's `assertDeliverable`: a replaced copy or one older than the receiver's accepted copy is `REPORT_OUT_OF_DATE`, the same copy to the same receiver again is `ALREADY_DELIVERED`; the channel `HPM_PUSH` is reserved for the adapter of ENT-2); `answerReportDelivery` (a demo copy is `TEMPLATE_UNCONFIRMED`, `demo_not_acceptable`); `listReportDeliveries`. Permissions `rpt.read|generate|check|approve|issue|deliver|answer`; the figures of `DIS-WEEKLY` also need `home.read` (the reader of the command center judges the scope).

**Demo mode** is read at generation and again at issue: `DEMO_FORMS` (a typo is `VALIDATION_FAILED`), else the rule `REPORT_FORM_MODE`, else off. **Screens**: RPT-01 catalogue and generation (period dialog by kind, reason asked when the server says a copy was issued with other figures), RPT-02 drafts, preview and the three-step flow, RPT-03 issued copies with the whole sha256, chain, files, deliveries and answers, RPT-04 delivery log (`apps/web/src/screens/rpt`).

- `scripts/build-demo-templates.mjs` (`npm run templates:build -w @machvon/edition-enterprise`; `templates:check` compares without writing): writes `templates/demo/<CODE>.demo.xlsx` (ExcelJS: styles, merged two-level header, number formats, formulas, A3 landscape, fit to one page wide, header rows repeated, print area, mark in header and footer) and `<CODE>.demo.docx` for the four narrative forms. Bytes are deterministic (fixed dates, normalised zip). The test suite fails when a committed template differs from what the layouts give.

Demo mode (R18):
- `assertLayoutIssuable(layout, { demoMode })` allows a DEMO layout only when demo mode is on (`TEMPLATE_UNCONFIRMED`, detail `demo_forms_off` otherwise); a READY layout needs nothing; PENDING_EXTERNAL and DRAFT are refused (`layout_status`) even in demo mode.
- Demo mode is `demoFormsOn({ env, ruleParams })`: the environment variable `DEMO_FORMS` (`true` or `false`; anything else is refused) wins; otherwise `demo_forms` of the governance rule `REPORT_FORM_MODE` (code `DEFAULT`, built-in default `false`; a tenant approves its own version); otherwise off. `demoFormsEnabled(rules, asOf, env)` of the enterprise package reads the rule the way the policy port gives it.
- Every output of a DEMO form carries "MẪU DEMO — chờ mẫu chính thức" (`DEMO_MARK`): a visible first row of the sheet (required by `validateLayout`), the print header and footer, the workbook properties, the Word header and footer, and the issued-copy metadata (`IssuedCopyMarks`).
- A DEMO form can never be marked READY (`assertStatusMove('DEMO', 'READY')` is `demo_not_ready`) and never counts as accepted (`countsAsAcceptedForm`, `countsAsAcceptedCopy`, `assertAcceptable`). `validateLayout` requires a DEMO layout to have no `formRef`, a name with "mẫu demo" and the mark in the preface.

To replace a demo form by the official one: get the official xlsx and docx; read its rows and columns into a NEW layout with the same code, a new `version`, `formRef` set to the decision or letter, and status DRAFT; store the template by sha256; write its golden test with the customer's file; set READY only after the owner confirms it matches (DRAFT to READY is the only way to READY). Then drop the form from `DEMO_FORMS` and from `templates/demo/` (the demo layout stays available for demo environments until then). The KPI codes of the strip must exist in the KPI register; the enterprise indicators depend on FND-1 (`docs/fnd-funding-model.md`), whose semantics spec is not approved yet (R15), so every figure on a demo form is "chưa kiểm chứng".

Known limits of the demo forms: the cumulative and capital columns of a project line are data fields the caller provides (the figure engine of FND-1 is not built); totals are formulas over the rounded cells of the lines, so with real data a total can differ by a rounding unit from the exact figure of the strip; when a group has more lines than the template holds, rows are inserted below its first line (formulas that point into another sheet are not rewritten; none of these do).

## PDF, the document model and layouts configured without code (ENT-4b)

**One document, three writers (R26).** `formDocumentOf(layout, narrative, data)` (kernel `report-document.ts`) fills a form once into a `ReportDocument`: the grid (what the Excel writer keeps in the template), the narrative (what the Word writer lays out) and the hash of the layout. `documentSheetOf` resolves the grid for a reader: formulas are worked out by the small evaluator `report-formula.ts` (SUM, MIN, MAX, AVERAGE, COUNT, ROUND, ABS, IF, IFERROR, arithmetic and comparison; anything else has no value and is reported in `unevaluated`, never guessed), numbers are written in the format of their cell. The PDF writer `apps/api/src/modules/reports/report-pdf.ts` prints that sheet (merged cells, header rows repeated on each page, rows kept whole, A4 portrait, A4 landscape from 7 columns, A3 landscape from 11, the demo mark in the head and foot of every page, a footer with the layout version, the period, the first 12 characters of the layout hash and the page number) followed by the narrative on pages of its own. It reuses the fonts and the wrapping of `dis/export-pdf.ts`. The bytes depend on the document and the last day of the period only.

**What is recorded.** The PDF is stored once per sha256 in `report_output_file` (format PDF), named by `file-name.ts` (`.pdf`), checked against its hash on every read (`getReportDraftFile`, `getReportIssueFile`, format `PDF`). It is a rendition, not a second source: the package digest of a copy is still the digest of the workbook and the Word file, so a report generated before the PDF existed is still a repeat. Draft and issued copy record `pdf_sha256` (and `pdf_name`) and `layout_sha256`; the issue trigger requires both to be those of the approved draft (migration V2760, block ENT4B-1 2760-2779). Performance: the PDF of a long form is held to the report budget of 20 seconds (row PB-R008 of docs/qa/perf-budget.json now measures the PDF, the heaviest file).

**Golden tests.** `apps/api/test/reports/three-writers.ts` makes the three files from one document and lists every disagreement: cell by cell (workbook against sheet; formulas re-evaluated from the formulas the file holds), the lines of the narrative (Word against PDF), the pages (count, order, repeated header, narrative after the sheet). Used for the six enterprise forms (`report-pdf.golden.enterprise.test.ts`, pages fixed in `test/reports/golden/pdf-pages.json`, regenerate with `UPDATE_GOLDEN=1`), the weekly form, a long form and the configured forms; a test shows the check can fail.

**Layouts chosen without code (R23).** Rule type `REPORT_LAYOUT` of the governance rule store (packages/kernel/src/report-layout-config.ts): code `CFG_*` (the rule type's `codePattern`), params = kind (INTERNAL or AGENCY_REQUEST, a form asked for by a Department, Board or Sector with the name of the body and its request), title, period kind, money unit, demo flag, the indicators (code, title, period basis), the columns of the project table from a fixed catalogue, project groups, totals, signatures, note and the id of the provider of the figures. Not free cell design. Versions, maker apart from submitter apart from approver and the audit (ADM-11) are those of the rule store and its screens. `compileLayoutConfig` turns the params into the layout of the engine (status DEMO with illustrative data and the mark when the demo flag is on, else READY and LIVE through the provider). `configured-forms.ts` offers the version in force today in the catalogue and for `generateReport`; the registry of code-owned forms refuses the `CFG_` prefix and a configured form cannot be addressed to the receivers of the official forms (PVN, HPM, the Ministry), which stay owned by code and packs. An issued copy keeps the version (`v<rule version>`) and the hash of the layout. Project groups read the dataset `projects_<group key>` from the provider; until the enterprise provider of ENT-3a fills it the cells stay empty and the grid says `DATASET_MISSING`, never made-up numbers. Two starting layouts are built in (UNVERIFIED): `CFG_AGENCY_REQUEST` and `CFG_INTERNAL_OVERVIEW`. `previewReportLayout` (POST /report-engine/layout-previews, permission rpt.generate, stores nothing) judges the params with the schema and fills the form with labelled illustrative data for the live preview. Screens RPT-07 (configured layouts, versions, submit, approve, withdraw) and RPT-08 (editor with preview), i18n part `ent4b`.

## Cross-report comparison of the same period before release (ENT-4a, CN.04)

Status: built (kernel, database, API, screen RPT-09). Plan: `docs/plans/ent4a.md`; migration block ENT4A-1 2880-2899 (`V2880`); module spec RPT.md, section "Làn ENT-4a"; story ST-RPT-141. Requirement: HSKT "Phan mem quan ly DTXD" v0.3, CN.04; eng review R21 (one read path), R26 (one document model), R18 (PENDING-EXTERNAL).

**What it does.** The reports of one period are set against each other before one of them is released. Two or more reports of the same organisation and period must give the same number; when they do not, the release of the reports involved is stopped (a difference at the BLOCKING level) until a person other than the preparer has recorded why the difference is right. The comparison never changes a figure. The parts a report can play (the layout code of each is a param of the rule): `PVN_MONTHLY`, `PVN_QUARTERLY`, `COMMITTEE` (board meeting, quarterly), `STEERING` (giao ban, monthly), `HPM_MONTHLY`; plus the frozen enterprise snapshot of the period, compared like one more report. The family of a period is its quarter and the three months of that quarter.

**Where the numbers come from (R21, R26).** A draft records the figures it was FILLED with when it is generated: the figures of its strip and the project rows of its datasets (`report_figure_set`, insert-only, sha256 of the canonical JSON). The comparison reads that record, never the cells of the Excel file, so it compares exactly what the files were made from and there is no second reader. A draft made before this lane has no record and is listed as skipped (`NO_FIGURES`), never as agreeing; generating the same bytes again records it. The frozen snapshot of the period is read through the provider of the forms (`ENT_SNAPSHOT`, which uses `EnterpriseFigureReader`, the one reader), so "report = snapshot" compares what was printed with what the reader says now; a report made from a snapshot revision that was corrected later is found stale. A form and a period are stood for by the head issued copy (newest revision), else the newest draft that is not issued; the draft about to be released stands for its own form and period.

**The rules (a closed set; the numbers are a governance rule).** XR-01 months to quarter (flow figures: the months of the pair sum to the quarter; point-in-time figures: the last month equals the quarter; pairs PVN quarterly from PVN monthly and board meeting from steering). XR-02 report equals snapshot. XR-03 same indicator, same number (HPM and PVN monthly, steering and PVN monthly, board meeting and PVN quarterly). XR-04 cumulative since the start does not exceed the total investment, in the strip and in every project row. XR-05 unit sum equals company total (the project rows added unit by unit equal the figure of the strip; a row with no unit is part of the finding and is named in the path). XR-06 a rate of the strip equals its numerator over its denominator (`percentOf` of the funding model) within the tolerance in points. Rule type `REPORT_CROSSCHECK`, code `DEFAULT` (kernel `report-crosscheck.ts`, `ent4a-rule-types.ts`, registered by `registerEnt4aRules`): roles with layout codes, `include_illustrative` (false: invented data proves nothing), the code lists of rates and counts, the total code, the row source (key, unit and the column that carries each figure), the rate definitions, and for each rule enabled, severity BLOCKING or WARNING, codes, roles, pairs, `absolute_vnd`, `scale` (dong, thousand, million, billion) and `pct_tolerance`. The built-in default is UNVERIFIED and every screen says so. Versions, maker apart from submitter apart from approver and the ADM-11 audit come from the existing rule store.

**Tolerance.** Figures are whole dong in decimal text and are compared as exact integers (`bigint`): the tolerance is `absolute_vnd` plus, for `n` rounded numbers, `n x unit(scale) / 2` (half a unit of the scale of the reports for each number; whole dong need no allowance). Counts are exact. Rates are compared in percentage points (`pct_tolerance`, default 0.01 point). The defaults are exact; a tenant that sends reports in million dong approves a version with `scale` MILLION_VND.

**Skipped, never passed.** A comparison without enough data is recorded with a reason and counted: `MISSING_REPORT`, `NO_FIGURES`, `ILLUSTRATIVE`, `NO_VALUE`, `NO_SNAPSHOT`, `DUPLICATE`. The result carries the coverage (reports, usable reports, rules run, comparisons made, skipped), so a gate that compared nothing says so and the screen does not read as a pass.

**Every number has formula, source and time.** A finding names the rule and its formula, the expected and actual value, the difference and the tolerance, and for each term the part, the layout code, the report (draft or issued copy and its revision, or the snapshot), the period, the row when it is about a project, the value, the source (the report as filled, its project rows, the snapshot with its revision) and the as-of day. The path lists the steps toward a correction (generate the named report again from the snapshot in force, assign a unit, complete a missing month, check the sources) and ends with the explanation. The fingerprint is the sha256 of the rule, the figure, the period and the values of the terms.

**Gate on release.** `issueReport` runs the comparison for the period of the draft (month or quarter, form with a part) and refuses with `REPORT_CROSSCHECK_BLOCKED` (409) when a BLOCKING finding that involves the draft has no explanation for its fingerprint. The refusal is committed with the audit row `rpt.report_issue_blocked` and lists the fingerprints. WARNING never blocks; a finding that involves only other reports does not block this release; a form with no part in the rule is released as before. When the copy is issued, `report_crosscheck_release` keeps the evidence: the hash of the result, the number of comparisons, the explained fingerprints and the warnings (audit `rpt.crosscheck_evidence_recorded`).

**Explanation (ADM-11 style).** `explainCrosscheckFinding` (permission `rpt.crosscheck.explain`, whole tenant): the server recomputes the comparison and looks the finding up by fingerprint (`CROSSCHECK_FINDING_NOT_FOUND` 404 when the figures changed); the reason has 20 to 2000 characters without blanks at the edges; the explainer must not have prepared any report involved (`SELF_APPROVAL_DENIED`; a trigger of the database checks the drafts and issued copies named in `involves`). One explanation per fingerprint: a repeat by anyone returns the first (`EXISTING`). Audit `rpt.crosscheck_explained` (the reason in the audit reason), outbox `rpt.crosscheck.explained.v1` with ids and codes only. The explanation holds for exactly those figures; a changed figure is a new fingerprint and needs a new explanation. Insert-only. Who holds the permissions: `TENANT_OWNER` (`rpt.*`); the committee system roles read the comparison (`rpt.crosscheck.read`) and only `COMMITTEE_HEAD` explains (migration V2881 for tenants seeded before); in the organisation pack `rpt.crosscheck.explain` is one of the decision permissions of the planning reviewer (never entry, administrators or viewers) and the planning reviewer and the leadership viewer read.

**API, screen, tests.** Operations `getReportCrosscheck` (GET `/report-engine/crosscheck?kind&year&index[&draft_id]`, `rpt.crosscheck.read`), `listCrosscheckExplanations`, `explainCrosscheckFinding`; `issueReport` lists the new error code. The controllers are in the public report module (`apps/api/src/modules/reports`): a public process has no form that plays a part, so the comparison is empty there, and nothing of the enterprise package is imported. Screen RPT-09 (`apps/web/src/screens/rpt/crosscheck`), reached from the draft screen RPT-02 and by address `?kind&year&index&draft`. Kernel tests `packages/kernel/test/report-crosscheck.test.ts` include a metamorphic test: a consistent family gives no finding, one change at a time (one dong, a missing month, a stale snapshot revision, a row without unit, cumulative above total, HPM differing from PVN) must be found, and the same changes are not found when every rule is switched off (the check can go red). Database `packages/db/test/report-crosscheck-store.test.ts`, API `apps/api/test/reports/crosscheck.enterprise.test.ts`, web `CrosscheckScreen.test.tsx`.

**Known limits.** The tolerances, the blocking levels, the code lists and the pairs are starting values (UNVERIFIED, D03) until the customer confirms them. The forms stay DEMO (R18): on invented data the comparison is skipped unless a tenant approves `include_illustrative`; nothing here is acceptance of an official form. Drafts made before this lane have no figure record (regenerate to compare). The HPM push (ENT-3c) is compared through the HPM monthly form, not through the pushed package.
