# The request path of the AI gateway (ST-LLM-005)

Module document: `Design/MACHVON_Design/01_Documents/05_modules/LLM.md` (F1, BR-LLM-01, BR-LLM-02, BR-LLM-06, BR-LLM-10). Tables `ai_request` and `llm_attempt` (baseline V002, guards in `V1145`). Operations: `requestAiCompletion` (`ai.invoke`), the reads `listAiRequests` and `getAiRequestRoute` (`llm.audit.read`) and `get_resources_llm_attempt` and `_id` (`llm_attempt.read`). Screens LLM-01 (overview) and LLM-05 (routing and fallback). Pure rules: `packages/kernel/src/llm-gateway.ts`; record: `packages/db/src/llm-gateway-store.ts`; path: `apps/api/src/modules/llm/gateway.service.ts` (`LlmGatewayService`, which other modules inject to ask for an answer) and `gateway.controller.ts`; the models are a port (`AiGatewayPort`, `LLM_GATEWAY`) with `MockAiGateway` until the adapter that goes through LiteLLM with the virtual key of the tenant is deployed.

## What a request does

1. **The caller names the sources and the input, never the class.** The body is `task_type`, `subject_module`, `source_refs` (`document_version_id` of each), `input_ref` (where the module keeps the input: a pointer), `input_sha256` and, optionally, an anonymisation attestation and `max_cost_vnd`. A field that is not in the contract, a class included, is `400 FIELD_NOT_ALLOWED`.
2. **The class is the highest class of the sources** (public < internal < confidential < personal < important core; personal is kept above confidential, which takes the same routes). The class of a document version is the source of truth, and a source that is not a document version of the tenant or whose file is not clean is `422 VALIDATION_FAILED` on `source_refs`. The class and the sources are kept with the request (`classification_basis`) and the database refuses to change them (`ai_request_immutable_guard`).
3. **The profile** in force for the task (PUBLISHED, ST-LLM-004) must take the class: a request above `max_classification` of the profile is refused. A task with no profile in force is `422 AI_ROUTE_NOT_ALLOWED` (`profile`) and nothing is recorded, because there is nothing to record it against.
4. **The routes** are those the policy in force allows for the class (`routesFor`; no policy published means the baseline with the international route off), within the routes of the profile, and the international route only for public data. The models are those of the profile that are APPROVED, on an active provider, take the class, and have a price in force with every figure known; the primary model of the profile comes first and the others in the order the profile lists them. None: `REJECTED_POLICY`, `422 AI_ROUTE_NOT_ALLOWED` (`max_classification`, `route` or `model` says which), kept as a request with its audit and event, and the same key gets the same answer.
5. **The budget** is held before a model is called, at the dearest estimate among the models it may fall back to (`estimateVnd` of the profile caps), against the tenant and, for a project, the project (LLM F3). `429 BUDGET_EXCEEDED` names the scope (a budget that does not stop answers `APPROVAL_REQUIRED:<scope>`, the approval task is left to the workflow), and so does an estimate above `max_cost_vnd` (detail `max_cost_vnd`); both are kept as `REJECTED_POLICY` and no model is called.
6. **The call.** Each model of the plan is called once, in order; a provider that refuses, fails or does not answer in time is an attempt that cost nothing known and the next model is called (a fallback only inside the routes of step 4: a confidential file whose domestic and self-hosted models fail is two attempts and `FAILED` `AI_ROUTE_EXHAUSTED`, never an international one). An answer that fails the checks of step 7 is asked for again from the same model once (`MAX_CHECK_RETRIES`) and is not sent to another. Before each call the route is checked again; an international call for data that is not public is not made, `llm_international_non_public_total` is counted (the alert `LLM_INTERNATIONAL_NON_PUBLIC` pages security) and the database refuses the attempt row too (`llm_attempt_intl_chk`). The model is given the tools of the profile, which are only tools that read.
7. **The checks.** The answer is JSON that follows the output schema of the profile; when the schema requires `citations` each answer carries at least one, and every citation points at a source of the request (one that points elsewhere does not exist). Failing: `REJECTED_NO_CITATION` (`NO_CITATION`) or `FAILED` (`INVALID_JSON`; the attempt is marked `INVALID_JSON`).
8. **The cost.** Every answer that was paid for is settled attempt by attempt (`LlmFinopsStore.settle`, once for each provider request id) and the last one releases what is left of the hold; nothing was paid: the hold is released. Calls that timed out and no answer: the request is `PENDING_RECONCILE` with the hold kept until the usage is known (BR-LLM-06). The request keeps the sum of what was settled.

## What is kept and what is not

The request keeps the class, the sources, the policy version (none for the baseline), the route, provider and model, the state and the reason, the hash of the input, the hash of the answer, the number of citations and the cost; each attempt keeps its number, kind, route, model, outcome, latency, tokens and cost. **Neither the text of the input nor the text of the answer is kept anywhere**: no column holds one, the audit row (`llm.request_routed`, `llm.request_rejected`) and the events (`llm.request.completed.v1`, `.failed.v1`, `.rejected.v1`) carry the class, the route and the attempts and no content, and what a provider says about a failure is dropped (only the kind of the failure is kept). The answer goes to the module that asked, through `LlmGatewayService.request`, not through the API, whose answer is the state of the request.

## The records and the screens

`listAiRequests` pages the requests newest first (cursor of the time to the microsecond and the id; filters `status`, `route_class`, `data_classification`, `task_type`) and its first page carries `summary`: the month (Viet Nam) by route and by state and the number refused. `getAiRequestRoute` answers `LlmRouteDecision`: the class, the sources it came from, the policy version (the nil identifier `00000000-0000-0000-0000-000000000000` when the baseline was in force, so that the contract keeps a uuid), the route, provider and model it ended on and every attempt. **LLM-01** shows the tiles (requests of the month, the share of each route with two places: 50 of 1,000 is 5.00 percent, those refused, those failed or without citations), the filters and the requests with a link to LLM-05; **LLM-05** shows the decision of one request and its attempts. Both read only, with the standard states.

## Assumptions and limits

- **The call is made inside the transaction of the command**, which is right for the stand-in; with a real provider (seconds) the admission, the call and the settlement are to be split into steps so that no row is locked while a model answers. The port, the plan, the checks and the records do not change.
- **Quotas** (`max_requests_per_day`, `max_concurrent`) have no acceptance criterion in this story and are not enforced yet; they stay with ST-LLM-006.
- **The right of the person over each source** (the ACL of a document version) is not checked here: the module that asks is trusted to name sources in the scope of its user, and the gateway checks that they are clean documents of the tenant. **Fields with a class** (not whole documents) are not sources yet.
- **The entitlement of the tenant to AI (SAS) and the kill switch** are other stories; the anonymisation attestation is kept with the request and does not lower the class.
- `ai.invoke`, `llm.audit.read` and `llm_attempt.read` are tenant-wide: who holds them on a unit only is refused.
- `ai_request.policy_version_id` is nullable (V1145) for a request made under the baseline.
