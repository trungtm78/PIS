## Decisions (owner rule 2026-11-08: deepest governance, extensibility, no scope cut)

- D1. **One pure kernel module, no new reader.** `report-crosscheck.ts` (kernel) holds `compareReports(period, reports, policy, options)`. It never reads a table and never reads a snapshot by itself: the figures of a report are the figures the report was FILLED with (`ReportFillData.figures` and the project rows of its datasets, which the enterprise forms read through `EnterpriseFigureReader`, R21), and the frozen snapshot of the period is given to the module as one more figure set made with the same reader (`snapshotFigures` of the enterprise forms). So "form = snapshot" compares what was printed with what the reader says now.
- D2. **The figures of a draft are recorded when it is generated.** Table `report_figure_set` (one row per draft, insert-only, the figures and the project rows as JSON, sha256 of the canonical JSON). Comparing the cells of an XLSX would make a second reader; comparing the recorded fill data compares exactly what the files were made from. A draft made before this lane has no set: it is listed as skipped (`NO_FIGURES`), never as agreeing.
- D3. **Rules are data, a governance rule type.** `REPORT_CROSSCHECK` (kernel `ent4a-rule-types.ts`, registered by `registerEnt4aRules`, code `DEFAULT`, default flagged UNVERIFIED, formula/source/as-of on the type): the roles (which layout code plays PVN monthly, PVN quarterly, board meeting, steering/giao ban, HPM monthly) and the closed list of rules, each with enabled, severity BLOCKING or WARNING, the figure codes it covers, tolerance in whole dong, the money scale the reports round to and the tolerance in percentage points for rates. The rule ids are fixed in code (a closed set, like the layout catalogue), the numbers are the tenant's. Versions, maker apart from submitter apart from approver and the ADM-11 audit come from the existing rule store.
- D4. **The rules.**
  - XR-01 `MONTHS_TO_QUARTER`: for the flow figures of a quarter (executed, disbursed, estimate in the period) the three monthly reports sum to the quarterly report; for the stock figures (since the start of the year, since the start of the project) the third month equals the quarter.
  - XR-02 `SNAPSHOT_MATCH`: the figure of any report (board meeting, steering, quarterly, monthly, HPM) equals the figure of the frozen snapshot of the same period read by the one reader; this catches a report made from a snapshot revision that was corrected afterwards.
  - XR-03 `SAME_INDICATOR`: pairs of roles for the same period (HPM monthly and PVN monthly, steering and PVN monthly, board meeting and PVN quarterly) give the same value of the same indicator.
  - XR-04 `CUMULATIVE_WITHIN_TOTAL`: the cumulative since the start does not exceed the total investment, in the headline and in every project row.
  - XR-05 `UNIT_SUM_EQUALS_TOTAL`: the rows of the projects, taken unit by unit, add up to the company figure of the strip; a row with no unit is part of the finding. The unit subtotals are in the finding so a reader can see where the difference sits.
  - XR-06 `RATE_CONSISTENT`: a rate of the strip equals its numerator over its denominator (as the pack defines it) within the tolerance in points.
  A rule with a missing counterpart is SKIPPED with the reason, never passed; the result carries the coverage (rules run, comparisons made, skipped with reasons), so a gate that compared nothing says so.
- D5. **Tolerance is the money rule, not a guess.** Figures are whole-dong decimal text and are compared as exact integers (`bigint`) with the tolerance `absolute_vnd + terms x unit(scale) / 2`, where the unit of the scale (dong, thousand, million, billion) is the one of `MoneyScale` of the report engine, so a sum of `n` figures that were each rounded half up to the scale may differ by at most `n` half units. Rates are decimal text compared in points with `tolerance_pct`. Defaults are exact (0) for dong and 0.01 point for rates.
- D6. **Every number has formula, source and time.** A finding names the rule, its formula text (Vietnamese catalog text), and each term with: role, layout code, report reference (draft or issue, revision), figure code, value, source (snapshot id and revision, or the dataset), as-of day. It also carries the expected value, the actual value, the difference, the tolerance and a fingerprint (sha256 of rule id, period and the terms' values). The explanation path is a short ordered list of steps computed from the finding (regenerate the report named from the newer snapshot, open the period if the snapshot is wrong, or explain).
- D7. **The gate is on `issueReport`.** The command runs the comparison for the period family of the draft (a month: that month, its quarter and the months of the quarter; a quarter: the quarter and its three months), picks for each role and period the head issued copy, else the newest open draft, and refuses with 409 `REPORT_CROSSCHECK_BLOCKED` when a finding of severity BLOCKING that involves this draft has no explanation for its fingerprint. WARNING never blocks and is shown. A finding that involves only other reports does not block this release. An explained finding passes; an explanation applies to ONE fingerprint, so changed figures need a new explanation. The result is recorded as evidence with the issued copy (`report_crosscheck_release`, insert-only, hash of the result).
- D8. **Explanation (ADM-11 style).** `explainCrosscheckFinding`: reason of 20 to 2000 characters, the fingerprint and rule id of an open finding the server recomputes (a fingerprint that is not a finding now is 404), the explainer must hold `rpt.crosscheck.explain` over the whole tenant and must not be the preparer of any report involved in the finding (403 `SELF_APPROVAL_DENIED`); idempotent on (tenant, fingerprint): a repeat by anyone returns the first (`EXISTING`), the Idempotency-Key header is declared; audit `rpt.crosscheck_explained` with ids, codes and hashes (the text of the reason is in the audit `reason`, as other lanes do), outbox `rpt.crosscheck.explained.v1`. Insert-only table `report_crosscheck_explanation`, a trigger refuses UPDATE and DELETE.
- D9. **Operations** (through `scripts/contract-patch.mjs`): `getReportCrosscheck` (GET `/report-engine/crosscheck`, query kind/year/index, optional `draft_id`), `explainCrosscheckFinding` (POST `/report-engine/crosscheck/explanations`), `listCrosscheckExplanations` (GET). Permissions `rpt.crosscheck.read`, `rpt.crosscheck.explain`. Error codes `REPORT_CROSSCHECK_BLOCKED` (409), `CROSSCHECK_FINDING_NOT_FOUND` (404), `SELF_APPROVAL_DENIED` (existing).
- D10. **Screen RPT-09** "So sanh cheo bao cao cung ky" (next free RPT id; RPT-07/08 are ENT-4b): choose a period, see coverage, the findings with their terms (formula, source, time), the explanation path, the form to explain, and the explanations given; the draft screen RPT-02 shows the blocked state through the error. i18n part `ent4a`, help entry, story/backlog/trace/test-case rows in `Design/MACHVON_Design/03_Engineering`, mobile card not done (optional).
- D11. **R18.** The forms stay DEMO; a report on ILLUSTRATIVE data is skipped by default (`include_illustrative` false: invented numbers prove nothing) and the result says `ILLUSTRATIVE`. The lane is acceptance-neutral: nothing here counts as acceptance of an official form.

## Tests per step
Kernel (`packages/kernel/test/report-crosscheck.test.ts`, node test runner; no database): each rule passes and fails, tolerance edge, skip reasons, fingerprint stability, metamorphic: a clean family of reports derived from one snapshot has no finding, and every injected perturbation (one figure +1 dong, a missing month, a stale snapshot revision, a row without a unit, cumulative above total) is detected, so the check can go red. DB lane (written, not run): `packages/db/test/report-crosscheck-store.test.ts`. API (unit lane where possible, DB lane written): `apps/api/test/reports/crosscheck.test.ts`. Web: `apps/web/src/screens/rpt/crosscheck/CrosscheckScreen.test.tsx`.

## Risks

## As built (differences from the design above)
- The controllers and the gate are in the public report module, not in an enterprise-only one: the comparison needs no enterprise import (the snapshot comes through the provider named by the form), a public process has no form that plays a part so the comparison is empty there, and the screen RPT-09 stays in module RPT.
- A refused release is committed with its audit row (`refuseAfterCommit`) so the attempt is on record.
- Not built: the mobile card (optional). Built afterwards (fix lap, UAT r1): `rpt.crosscheck.read` is granted to the three committee system roles and `rpt.crosscheck.explain` to `COMMITTEE_HEAD` only (V2881 for tenants seeded before); in the organisation pack `rpt.crosscheck.explain` is a decision permission (the planning reviewer holds it, entry, administrators and viewers never do, `SOD_DECIDES`) and the planning reviewer and the leadership viewer read the comparison. The explainer is never the preparer of a report involved in the finding (kernel and database).
