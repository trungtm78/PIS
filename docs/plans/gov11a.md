## Per-item scope (the owner rule: deepest governance, no scope cut)

### CAP (G1-12): reallocation by performance, impact simulation, approval by delegation
Builds on kernel `cap-reallocation.ts`, `dis-forecast.ts` (`estimateYear`, `REALLOCATION_THRESHOLD_PCT`), `dis-rates.ts` (`rateOfSums`, `addSums`), db `cap-reallocation-store.ts`, `dis-snapshot-store.ts` (`rateSums` by PROJECT), `dis-forecast-store.ts`, DoA (`doa.ts`, `doa-matrix-store.ts`, `apps/api/src/doa-delegation.ts`), controllers `apps/api/src/modules/cap/reallocation.*`.
- Kernel `cap-reallocation-impact.ts` (pure): per project sums from the basis snapshot -> `simulateReallocation` applying the moves to the plan denominators (PM/LOCAL split by origin, bucket) -> before/after rates for the province, per unit and per project using `rateOfSums`; a projected year-end view using `Estimate` (donor projected disbursement capped at its new plan, recipient gains `absorption_pct` of what it receives capped by new plan); warnings (donor below floor, recipient already above plan, zero denominators, partial coverage). GOLDEN TEST: with no moves before === after === `rateOfSums(addSums(...))` and equals the rates of the DIS rates reader for the same fixture; also a move inside one unit leaves that unit's rate unchanged and a province move between units changes only those two units, province total rate unchanged (plan total unchanged).
- `reallocationCandidates`: donors/recipients ranked by performance (projected ratio vs plan) with suggested amounts, from rule `REALLOCATION_POLICY` (code DEFAULT: donor_max_ratio_pct 80 = REALLOCATION_THRESHOLD_PCT, donor_keep_margin_pct, recipient_min_ratio_pct, absorption_pct, min_move_vnd, max_share_of_donor_plan_pct, simulation_required, delegation_document_type 'CAP_REALLOCATION'), UNVERIFIED.
- DB V2560: immutable `reallocation_impact` evidence (proposal id + proposal version, basis snapshot, policy rule version, assumptions, before/after json, sha256, recorded by/at), RLS, tenant-leading indexes, append-only guard trigger. Submit records it (inside the submit transaction, in the service so API and workflow paths both do it); decide refuses a proposal whose impact was not recorded when the policy says `simulation_required` (new error code); decide and apply are checked against the DoA band of document type `CAP_REALLOCATION` for the total (unit = scope unit; `unconfigured: ALLOW` so tenants without bands keep today's behaviour), reusing the logic of `assertWithinDelegation` without a CommandScope (the service also runs from the workflow).
- API (reads): `GET /reallocation-proposals/{id}/impact` (frozen record for SUBMITTED and later, live simulation for DRAFT), `GET /reallocation-candidates` (query snapshot_id optional = latest frozen, plan_year, unit_id). Web: one screen of module CAP (candidates by performance, pick moves, simulation panel before/after with 'i' on every rate, delegation line showing who may approve, the impact attached to the proposal detail), with the states matrix.
